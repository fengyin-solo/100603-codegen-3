# 机场地面保障作业管理平台

面向航班保障、机位分配、廊桥靠接、摆渡车调度、行李装卸、航油加注、除冰作业与延误处置的一体化机场地面保障作业工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 应急演练与预案管理

预案在「应急预案管理」页维护**适用场景、启动条件、参演岗位**，再在「应急演练计划」页按预案排期。
该域规则集中在 `frontend/src/api/drill-service.ts`（数据存 `airport-ground-ops:drill-domain:v1`），与通用
`local-service.ts` 的自由动作流转不同，演练状态是强约束：

- **排期互斥**：同一预案在同一时段最多只有一场**在办演练**（待排期/已通知/进行中）；时段按半开区间
  比较，首尾相接不算撞车，已评估的演练释放名额。撞车时谁先办的依据固定为：**创建时间更早者先办，
  时间相同则演练编号靠前者先办**，后来的排期/改约直接被拦下并提示占用方。
- **整批通知、逐条确认**：一次勾选多个参演岗位整批下发，逐条登记每个岗位「确认收到 / 未确认」；
  未确认的岗位留在待通知队列继续补发，已确认岗位不回退、照常往下走。首轮下发后状态 待排期 → 已通知。
- **状态不许跳步**：只能 待排期 → 已通知 → 进行中 → 已评估 顺次推进。开始演练要求所有岗位至少下发过
  一轮且至少一个岗位确认；**没通知到的岗位（仍为「待通知」）不许直接进评估**，未确认岗位按缺岗记入结论。
- **结论唯一**：同一场演练重复提交评估只保留一条结论（提交次数累加），旧缺项整条作废、以本次清单为准。
- **缺项同源**：评估产生的缺项直接落到机坪安全巡查的整改清单，巡查页（`apron`）与演练页通过同一个
  `listDeficiencies()` 读取口读同一份数据，缺项条数必然一致；整改在巡查侧按
  待整改 → 整改中 → 已复查 推进。

规则验证脚本：`test/drill-rules.ts`（21 条断言，内存 localStorage 下跑通上述全部规则）。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `airport-ground-ops:entries` 这一项，或调用 `resetModule(模块)`。
  应急演练域单独存于 `airport-ground-ops:drill-domain:v1`，重置调用 `resetDrillState()`。
